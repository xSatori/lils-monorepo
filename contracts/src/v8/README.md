# Rounds V8 release candidate

V8 uses a separate factory and new clones. V7 and older contracts are not upgraded or rewritten.

The round captures `block.number - 1` during creation and reads `getPriorVotes` through the configured Lil Nouns adapter. Acquiring, transferring, or delegating voting power after creation does not increase a wallet's voting limit for that round. There is no later snapshot action or custom snapshot override. Wallet-based limits are not person-level Sybil protection: someone can split voting power across wallets before creation. Self-voting prevents a submission's owner address from voting for that submission; it cannot identify alternate wallets controlled by the same person.

After voting ends, anyone can call `finalizeBatch(maxEntries)` with `1 <= maxEntries <= MAX_FINALIZATION_BATCH`. The contract advances its persistent cursor exactly once per submission, skips non-approved entries, and carries a leaderboard with earlier submission IDs winning ties. It emits progress, but only sets `finalized`, records `finalizedAt`, emits final winners, and enables vault claims after the cursor reaches `submissionCount`. An empty round can be finalized with one nonzero batch request. The maximum batch must remain covered by a cold-storage gas regression below 8,000,000 gas; never substitute a larger block gas limit for the per-transaction ceiling.

On mainnet the only global admin is the immutable multisig address `0xeE09d7138B34EAC649ff0CEBE43f258464537701`. The mainnet factory constructor rejects any alternate admin. On Sepolia a separate immutable two-owner ERC-1271 contract admin is required, and the factory checks that it has code. Test admin owners are supplied explicitly at deployment; deployment alone does not prove they control the keys or can operate the admin. No Safe is created or modified by this release. Vault privileged actions require both the global contract admin and one currently eligible round recovery admin, as distinct addresses. Delayed safety execution rechecks that pairing. The vault's EIP-712 domain version changes to 3 for V8; V7 signatures are not reusable.

The creator must disclose that a fee-on-transfer ERC-20 may deliver less than its nominal prize allocation. Vault accounting records the actual amount received and preserves reentrancy protection. The fixed Lil Nouns mainnet treasury receives the creation fee even on Sepolia, where this is accepted test ETH and not an operational Sepolia treasury.

Before a Sepolia broadcast: run all Foundry and frontend checks, inspect deployed runtime sizes and exact cold-batch gas, confirm the adapter and both owner addresses, simulate from the disposable deployer, check balance/nonces, then independently review the transaction list. Afterward check receipts and runtime bytecode, factory fee/treasury/admin/adapter/version, ERC-1271 two-owner signatures, a creation snapshot, a complete 1,000-entry rehearsal where practical, claims/recovery, sponsored uploads, and frontend address mapping. Independent security review remains required before mainnet; Sepolia deployment alone is not a mainnet approval.

The Sepolia deployment record is [`deployments/sepolia-rounds-v8.json`](../../../deployments/sepolia-rounds-v8.json). Four deployment receipts succeeded, and postflight compared the deployed runtime with local artifacts outside compiler-patched immutable references. All four deployment contracts subsequently returned `Pass - Verified` on Sepolia Etherscan. The test admin's two-owner signing operation and live creation/snapshot/finalization/claim/recovery rehearsal remain unverified. Explorer publication and a hosted Preview do not establish mainnet readiness.
