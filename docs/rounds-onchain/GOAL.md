# Onchain Lil Nouns Rounds Goal

Build a production-oriented, chain-authoritative Lil Nouns Rounds protocol in this monorepo. Any address may pay the exact configured ETH creation fee to a versioned factory; the fee is delivered atomically to the configured treasury and an isolated, atomically initialized round clone is created for the caller.

The contracts, not the web app, database, API, or indexer, own lifecycle timing, round and submission configuration, admin membership, moderation status, snapshot configuration, voting allocations and totals, and deterministic final results. Version 2 adds an immutable creator-selected moderation-review interval between submission close and voting start; the production UI defaults that interval to one day. Content too large for storage is represented by bounded content-addressed URIs plus integrity hashes.

The factory always has exactly two independently authorized global admins. A round creator is its first round admin and controls additional round-admin membership. Global admins govern factory creation and future implementation versions but cannot rewrite votes, select winners, or replace immutable round configuration.

The version-2 and version-3 test profiles use five-minute submission, moderation-review, and voting phases, a test historical-votes token when the real token is unsuitable, and disposable test accounts. Test mode is forbidden on Ethereum mainnet. The mainnet Lil Nouns token (`0x4b10701Bfd7BFEdc47d50562b76b436fbB5BdB3B`), treasury (`0xd5f279ff9EB21c6D40C8f345a66f2751C4eeA1fB`), and governor (`0x5d2C31ce16924C2a71D317e5BbFd5ce387854039`) were verified by read-only chain calls; the production creation fee remains `UNKNOWN`. Mainnet deployment and transactions are separately gated and are not authorized by this work.

Version 3 adds one immutable, factory-bound prize vault per round. The vault stores the authoritative prize plan, accepts ETH/ERC-20/ERC-721/ERC-1155 funding, preserves contributor refunds until sealing, and releases each allocation permissionlessly to the deterministic onchain winner. A delayed two-signature recovery path can move only verified excess or expired allocations, rotate the recovery recipient, and never consume active winner liabilities or contributor credits. Version 1 and version 2 rounds retain their historical descriptive-metadata-only awards model.
