# Onchain Rounds Threat Model

Prize-custody-specific analysis is in [PRIZE-VAULT-THREAT-MODEL.md](./PRIZE-VAULT-THREAT-MODEL.md).

## Assets and trust boundaries

Assets are creation fees, authoritative configuration, admin authority, submissions, historical eligibility, vote accounting, and final results. Untrusted inputs cross through every payable/configuration/submission/vote transaction, content URI, treasury callback, and indexed event projection.

| Threat                                       | Severity | Control / residual risk                                                                                                                                                                                                                                                                                           |
| -------------------------------------------- | -------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Clone initialization takeover                | Critical | Implementation disables initialization; factory clones and initializes atomically; initializer is one-shot.                                                                                                                                                                                                       |
| Deterministic-address front-running          |     High | Salt binds creator, creator nonce, version, config hash, and caller salt; only the creator's transaction advances its nonce.                                                                                                                                                                                      |
| Fee forwarding/reentrancy                    |     High | Exact fee, checks/effects before external delivery, factory reentrancy guard, and creation reverts on failed delivery. Tests prove the paid creation fee is not retained; arbitrary forced ETH cannot be prevented.                                                                                               |
| Malicious treasury receiver                  |     High | Failure reverts the whole creation; admins must rotate to a receiver able to accept ETH. No fallback retention.                                                                                                                                                                                                   |
| Global-admin compromise                      |     High | Either admin can affect future creation/config but cannot pause or mutate existing rounds, votes, configuration, or results. Rotation is atomic and cannot duplicate/zero admins. Operational use of a Safe/timelock is recommended for production.                                                               |
| Creator-supplied voting adapter              | Critical | Factory construction pins one code-bearing adapter immutably; every round config must equal it. Rogue adapters revert before clone deployment.                                                                                                                                                                    |
| Creator/admin censorship                     |   Medium | Admins can reject/hide before voting. Submission close creates a visible review-only interval, all actions are public events, and moderation freezes at voting start. This is an explicit governance risk.                                                                                                        |
| Phase-boundary manipulation                  |   Medium | `block.timestamp` controls phases; initialization enforces strict submission-open, submission-close, voting-start, and voting-end ordering. Proposer timestamp latitude is small relative to production durations. Test mode is visibly short and test-only.                                                      |
| Delayed snapshot capture                     |     High | First capture uses the prior block and is permissionless, but a delayed call shifts the effective boundary. UI/keeper must capture promptly; residual risk is documented.                                                                                                                                         |
| Round-pause censorship                       |     High | No per-round pause exists. Only future factory creation can pause, so global admins cannot consume a fixed voting window while writes are disabled.                                                                                                                                                               |
| Live voting-power manipulation               | Critical | All voting reads immutable historical snapshot power; live balance/current votes are never used.                                                                                                                                                                                                                  |
| Self-voting                                  |     High | Submission owner is stored from `msg.sender`; canonical address equality rejects allocations to own entries.                                                                                                                                                                                                      |
| Additive-vote double spending                | Critical | Cumulative used-votes state is updated atomically and bounded by strategy allocation.                                                                                                                                                                                                                             |
| Duplicate allocations                        |     High | Duplicate submission IDs in a call revert; cumulative per-entry caps apply across calls.                                                                                                                                                                                                                          |
| Submission spam                              |   Medium | Exact per-wallet and bounded total-submission caps; factory creation fee limits round spam.                                                                                                                                                                                                                       |
| Unbounded storage/loops                      |     High | URI bytes, total submissions, batch size, and winner count are bounded.                                                                                                                                                                                                                                           |
| Denial of finalization                       |     High | Bounded O(submissions \* winners) computation; gas must be measured at maximum configuration before launch.                                                                                                                                                                                                       |
| Metadata mutation                            |     High | Contracts allow only nonempty `ipfs://`/`ar://` URIs and reject mutable web schemes. URI and metadata hash become immutable with the stored record. Title/description hashes and exact UTF-8 byte lengths are committed onchain; clients verify fetched fields before display.                                    |
| Hidden/malformed content                     |   Medium | UI treats content as untrusted, sanitizes rich text, bounds fetches, and shows content-unavailable without hiding onchain fields.                                                                                                                                                                                 |
| Indexer lag/empty index                      |     High | Events are rebuildable; direct factory/round reads are the critical fallback. Empty index is never proof of empty chain state.                                                                                                                                                                                    |
| Chain/replay confusion                       |     High | UI/address config is keyed by chain ID and writes require exact supported chain; signatures are not used for writes.                                                                                                                                                                                              |
| Test-mode deployment on any unintended chain | Critical | Factory construction allows test mode only on chain IDs `31337`, `1337`, and Sepolia `11155111`; scripts also assert chain ID.                                                                                                                                                                                    |
| Trapped ETH                                  |     High | Factory receive/fallback reject ETH and round receive rejects ETH; exact fee is immediately forwarded.                                                                                                                                                                                                            |
| Unauthorized implementation changes          | Critical | Only current global admins register versions; versions are append-only and existing clones never upgrade. Implementation code length is checked.                                                                                                                                                                  |
| One-admin or replayed media mutation         | Critical | V5 requires two distinct current global/round admins, EIP-712 chain/round/submission/nonce/content/deadline binding, `SignatureChecker` ERC-1271 support, and a consumed monotonic nonce. Images are append-only and freeze at voting start.                                                                      |
| Declared original-image count mismatch       |   Medium | The contract caps declared originals plus additions at eight; backend/UI reconcile fetched metadata exactly and cap rendering. Solidity cannot inspect external metadata, so unavailable manual metadata is visibly treated as unverified content.                                                                |
| Last-block pre-vote image append             |   Medium | Accepted product tradeoff: the moderation buffer remains usable through `votingStart`. The permanent event indexes submission and both approvers and records revision, executor, URI, and hash.                                                                                                                   |
| Stateless Pinata replay/provider billing     |      Low | V5 retries are bound to existing onchain commitments and exact CAR bytes; the route returns no generic upload capability and rejects provider CID mismatch. Three simultaneous identical uploads produced one provider record with the exact CID. Hosting rate limits, monitoring, and Pinata billing alerts remain operational controls. Historical pre-V5 PostgreSQL authorization is isolated and rejects V5 rounds. |
| Zero/duplicate/lost admins                   |     High | Nonzero/distinct factory admins; rotation preserves two; round cannot lose its last admin before finalization.                                                                                                                                                                                                    |
| Arbitrary winner selection                   | Critical | Finalizer supplies no winners; contract derives and freezes deterministic IDs.                                                                                                                                                                                                                                    |

## Security gates

- Unit/integration tests cover documented critical/high controls. The stateful handler actively attempts snapshot recapture, self/duplicate/invalid/over-cap voting, post-boundary moderation, generic role mutation, reinitialization, and a second paid factory deployment while asserting accounting, frozen eligibility, admin count, provenance, fee forwarding, and finalization invariants.
- Contract size and maximum finalization gas are measured.
- Slither 0.11.3/solc 0.8.24 completed with no critical/high issue; informational and false-positive results were manually triaged in the deployment record.
- No critical/high finding may remain open before Sepolia deployment.
- Sepolia evidence does not authorize mainnet deployment.
