# Yellow Rounds Parity Matrix

| Yellow behavior                              | Classification              | Lil Nouns implementation                                                                                                                                           |
| -------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Draft state                                  | INTENTIONAL SECURITY CHANGE | Permissionless creation publishes immutable timing/config immediately; clients may keep an offchain draft before signing.                                          |
| Upcoming state                               | PORTED ONCHAIN              | Derived from `block.timestamp < submissionsOpen`.                                                                                                                  |
| Submissions-open state                       | PORTED ONCHAIN              | Timestamp-gated submission writes.                                                                                                                                 |
| Moderation review buffer                     | INTENTIONAL SECURITY CHANGE | Version 2 closes submissions before voting and leaves an immutable creator-selected review interval; the production UI defaults to one day.                        |
| Voting-open state                            | PORTED ONCHAIN              | Timestamp-gated voting after snapshot capture.                                                                                                                     |
| Ended state                                  | PORTED ONCHAIN              | Derived from voting end.                                                                                                                                           |
| Archived state                               | PORTED ONCHAIN              | Round-admin presentation flag after finalization; results remain immutable.                                                                                        |
| Ordered lifecycle timestamps                 | PORTED ONCHAIN              | Validated once during initialization.                                                                                                                              |
| Public metadata, images, long-form content   | PORTED ONCHAIN              | Bounded `ipfs://` or `ar://` URI and integrity hash; mutable web schemes revert and content bytes remain offchain.                                                 |
| Awards                                       | PORTED ONCHAIN              | v1/v2 preserve descriptive metadata URI/hash. v3 additionally commits an immutable prize-plan hash and deploys a bound vault; long-form award presentation remains content-addressed metadata.  |
| Project and trait submission types           | PORTED ONCHAIN              | Generic enum values `PROJECT`, `TRAIT`, and `OTHER`.                                                                                                               |
| Per-wallet submission limit                  | PORTED ONCHAIN              | Enforced in `submit`.                                                                                                                                              |
| Multiple ordered submission images           | PORTED ONCHAIN / INDEXED VIEW | V1-V4 retain metadata arrays. V5 additionally stores bounded append-only image URI/hash records and signer/executor audit onchain; clients merge them in order. |
| Two-admin post-submission image assistance    | INTENTIONAL SECURITY CHANGE | V5 allows two distinct current global/round admins to append, never replace or remove, images before voting. This explicit cross-round global-admin content authority did not exist in Yellow. |
| Pending/approved/rejected/hidden submissions | PORTED ONCHAIN              | Version 4 restores Yellow's auto-approval: submissions start approved and remain eligible unless an admin rejects or hides them before voting. Historical v1-v3 pending behavior remains immutable. |
| Round title/description limits               | PORTED ONCHAIN              | Per-round min/max values enforce exact UTF-8 byte lengths in `submit`; only hashes and byte lengths are stored while strings remain in content-addressed metadata. |
| Configurable winner count                    | PORTED ONCHAIN              | Bounded and fixed at initialization.                                                                                                                               |
| One vote per eligible wallet                 | PORTED ONCHAIN              | Positive historical delegated power gates one allocation.                                                                                                          |
| Delegated NFT voting power                   | PORTED ONCHAIN              | `getPriorVotes` adapter at immutable captured block.                                                                                                               |
| Fixed votes per eligible wallet              | PORTED ONCHAIN              | Positive historical power gates fixed allocation.                                                                                                                  |
| Base plus delegated power                    | PORTED ONCHAIN              | Positive historical power gates base plus snapshot power.                                                                                                          |
| Snapshot at voting start                     | PORTED ONCHAIN              | Permissionless first capture at/after start uses `block.number - 1`; exact start-time block lookup is not available to a contract.                                 |
| Custom snapshot                              | INTENTIONAL SECURITY CHANGE | Custom historical block is fixed at initialization and must precede creation/current block; admins cannot choose after start.                                      |
| Additive multi-transaction voting            | PORTED ONCHAIN              | Allocations only increase.                                                                                                                                         |
| Immutable submitted votes                    | PORTED ONCHAIN              | No move, reduction, edit, or deletion path.                                                                                                                        |
| Per-entry vote cap                           | PORTED ONCHAIN              | Cumulative voter-to-entry cap.                                                                                                                                     |
| Remaining-vote enforcement                   | PORTED ONCHAIN              | Total used cannot exceed strategy allocation.                                                                                                                      |
| Case-insensitive self-vote prevention        | PORTED ONCHAIN              | EVM address equality is canonical.                                                                                                                                 |
| Voting only for approved submissions         | PORTED ONCHAIN              | Eligible set is approved/non-hidden and frozen at voting start.                                                                                                    |
| Deterministic winner finalization            | PORTED ONCHAIN              | Vote total descending, then earlier submission ID.                                                                                                                 |
| Public vote activity                         | PORTED AS INDEXED VIEW      | Canonical allocations/totals are storage; activity is reconstructed from events.                                                                                   |
| Per-submission voter lists                   | PORTED AS INDEXED VIEW      | Rebuilt from allocation events.                                                                                                                                    |
| Round request/admin approval                 | INTENTIONAL SECURITY CHANGE | Replaced with exact-fee permissionless factory creation.                                                                                                           |
| Admin review/moderation                      | PORTED ONCHAIN              | Round admins may moderate through the dedicated review interval and freeze exactly when voting begins.                                                             |
| CSV/ZIP exports                              | PORTED AS INDEXED VIEW      | Generated from events and direct reads; never authoritative.                                                                                                       |
| Admin vote correction/edit/delete            | INTENTIONAL SECURITY CHANGE | Removed; votes are append-only and immutable.                                                                                                                      |
| Database transaction locking                 | INTENTIONAL SECURITY CHANGE | Replaced by atomic EVM transitions and reentrancy controls.                                                                                                        |
| Dedicated prize custody                      | INTENTIONAL SECURITY CHANGE | Yellow awards were descriptive only. v3 gives each round a factory-bound vault with an immutable ETH/ERC-20/ERC-721/ERC-1155 allocation plan; v1/v2 remain unchanged. |
| Permissionless prize release                 | INTENTIONAL SECURITY CHANGE | After deterministic finalization, anyone may trigger an allocation release; the vault derives the winner and recipient from authoritative round state rather than an admin-supplied winner list. |
| Winner-directed alternate recipient          | INTENTIONAL SECURITY CHANGE | A winner may authorize `claimTo` with an exact-asset, plan, chain, vault, nonce, recipient, and deadline-bound EIP-712 signature; successful allocations are at-most-once. |
| Underfunded-plan cancellation/refunds        | INTENTIONAL SECURITY CHANGE | A v3 vault that cannot seal may be canceled after submissions open; contributors reclaim only their recorded credits.                                               |
| Admin prize recovery                         | INTENTIONAL SECURITY CHANGE | No unilateral release exists. V4 adds allocation-specific two-signature hold/unhold and delayed reclaim to the fixed recovery recipient. This deliberately lets a quorum seize a held winner allocation; the UI and events expose that trust boundary. |
| Recovery signer model                        | INTENTIONAL SECURITY CHANGE | Exactly two distinct live signers are required: global/global, global/frozen recovery-eligible round admin, or two frozen recovery-eligible round admins.            |
| Public prize execution delay                 | INTENTIONAL SECURITY CHANGE | Anyone may execute distribution, but v4 opens public release only after an immutable post-finalization safety window so a two-admin hold cannot be raced. |
| Exact Yellow winner tie behavior             | INTENTIONAL SECURITY CHANGE | Yellow resolves equal totals newer-first; the contract uses earlier submission ID for a simpler stable deterministic rule.                                         |
| Legacy production data import                | OUT OF SCOPE                | No Yellow production data is imported or modified.                                                                                                                 |

The product-policy parity choice is explicit: all four strategies require positive delegated Lil Nouns voting power at the immutable snapshot.
